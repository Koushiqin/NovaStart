# P6 · F6 信箱与投递实现计划

> **For agentic workers:** 按 `.agents/skills/executing-plans` 逐任务执行。步骤用 `- [ ]` 追踪。

**Goal:** 每场有效学习获得 1 次投递机会：填收件人投递，正文=本场感想（无感想=任务内容）；对方未处理信箱满 3 拒收、不消耗机会可改寄；收件人不存在明确提示；结算第③步逐封收藏/放弃；历史信箱 ≤100 懒清理；未收藏当日 24:00 懒失效；发出记录标「已投递/未送达」；学习期间静默投递，结算页显示「你专注时收到 N 封信」。

**Architecture:** Letter 表迁移加 `sender_id`、`status`（delivered/undelivered）、`focused_delivery`。重写 `letter_service.deliver` 的事务顺序：成功才占 `ActionLog("deliver")` 幂等键；满 3 → 只写 sender 的 undelivered 记录（不占键 → 不消耗机会）。行锁 `with_for_update` 保并发 ≤3。新增 send/dismiss/outbox 端点；前端替换结算②③占位组件 + 新增 `/mailbox` 页（新页面理由写 Spec）。种子给小明预置 2 封未处理信。

**Tech Stack:** FastAPI + SQLAlchemy（行锁/唯一约束）+ Alembic；React 18。

**Spec:** [docs/specs/006-f6-mailbox.md](../../../docs/specs/006-f6-mailbox.md)（执行时从模板复制）。

**Depends on:** P4（settle 占位组件与 advance）、P5（「当天完成」门槛口径、summary 扩展机制）。

**Produces（后续计划依赖的接口）:**
- `POST /api/letters` `{session_id, recipient_name}` → `{result: "delivered" | "rejected_full" | "rejected_unknown" | "already_sent", letter_id: int | null, server_time}`。
- `POST /api/letters/{id}/dismiss` → `{letter, server_time}`（幂等；过期 → 409 `{code:"LETTER_EXPIRED", message:"这封信已经过了一天"}`，favorite 过期同样 409）。
- `GET /api/letters/outbox` → `{letters: [{id, recipient_name, content, status, created_at}], server_time}`。
- P4 summary 的 `received_during_session` 字段填真实值（本场 started_at→ended_at/now 内 delivered 计数）。
- LetterOut 扩字段：`sender_name`、`status`、`focused_delivery`（P7/P8 如需直接复用）。

## Global Constraints

- 同 P1 全部；另：未处理 ≤3 的不变量只有 letter_service 一条写入路径（行锁+事务）；收藏/放弃/投递幂等键走 `action_log` 唯一约束；已失效信不可再操作。
- 正文来源口径：Reflection 存在 → 其 content；否则 DayTask.raw_text（当前采用版口径=任务原文，A2）。

## Review Focus

1. 并发：两个发送方同时投给已有 2 封未处理的用户 → 恰好 1 封成功（Task 2 双事务/双连接测试钉住）。
2. 满 3 拒收 → 发送方机会不消耗：同一 session 改寄他人成功（Task 2 钉住）。
3. 收件人不存在 → `rejected_unknown`，无 ActionLog、无 Letter 行（Task 2 钉住）。
4. 重复点发送 / 重复收藏 / 重复放弃 → 各只生效一次（Task 2 钉住）。
5. 24:00 边界：过期信不出现在 inbox、收藏返回 409（Clock 注入钉住）；历史信箱 101 封 → 读时删最旧留 100（Task 2 钉住）。
