# Review

## 何时使用

每次功能开发收尾；或用户要求审查某次改动时。

## 使用前必读

- 本次改动的 `docs/specs/NNN-*.md`
- `docs/architecture.md`

## 步骤

1. **需求符合性**：逐条对照 Spec 第 3 节验收条件，每条给出「满足 + 证据」或「不满足 + 差距」。
2. **架构边界**：
   - 依赖方向是否仍是 `routers → services → models`（跑 `tests/test_architecture.py`）。
   - 是否引入重复状态 / 平行写入 / 第二取时间入口。
   - 改动是否落在 Spec 第 4 节声明的模块内。
3. **异常行为**：幂等（重复提交）、并发（信箱行锁）、跨零点、断网刷新恢复——与改动相关的场景是否仍成立。
4. **测试质量**：测试是否从验收条件推导，而非复述实现；是否区分「已编写」与「已运行通过」。
5. 结论写入 Spec 第 8 节；发现问题先修复再收尾，原因不明的失败上报用户，不得放宽检查。

## 禁止

- 无证据宣布「完成」「已通过」。
- 为通过 Review 删断言、扩大白名单、跳过测试。

## 完成判定

验收条件条条有证据，边界检查通过，Spec 第 8 节无隐瞒项。
