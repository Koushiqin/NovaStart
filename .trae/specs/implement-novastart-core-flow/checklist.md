# Checklist

## 契约与迁移

- [ ] 所有新增/变更字段先落 `schemas/` 与 `models/`，再生成 Alembic 迁移；迁移 `downgrade base → upgrade head` 双向通过
- [ ] `users` 含 `avatar_color / streak_current / longest_streak / total_completed_days / last_completed_date`，`name` 唯一
- [ ] `day_tasks` 含 `status / split_source / split_for_text / original_starter_step / original_steps`，`(user_id, date)` 唯一
- [ ] `sessions` 的 `duration_sec` 仅有效场次写入，`status` 语义为 `active|completed|settled|discarded`，`(user_id) WHERE status='active'` 部分唯一约束生效
- [ ] `stars` 表存在且 `(user_id, date)` 唯一
- [ ] `letters` 为 `sender_id / recipient_id / status / delivered_during_focus`，`handled` 已删除且历史数据已回填
- [ ] `reflections.session_id` 唯一（同一场只能写一次感想）

## F9 身份与演示

- [ ] 业务请求缺少 `X-User-Id` 时返回 400 `MISSING_USER`，且不写数据
- [ ] 切换账号后首页/记录/信箱数据整体切换，请求头随之变化
- [ ] 3 个演示账号；种子含 A 连续 6 天 + 未处理信箱 2 封、B 有一条历史记录
- [ ] 演示加速开启后真实 60 秒判满 5 分钟，关闭后恢复真实时间；加速与时间旅行只改 `clock.py` 一处
- [ ] `/dev/reset-seed` 可重复执行，计数一致，不需要手工准备多套数据

## F1+F2 今日任务与拆分

- [ ] 同一天只有一个任务；修改标题更新同一行而非新建
- [ ] 计时开始后编辑返回 409 `TASK_LOCKED`
- [ ] 首次进入展示引导语 + 示例标签，不出现空白页
- [ ] 昨日未完成提示「要不要接着来」，一键带入且不自动继承
- [ ] 拆分结果 starter 必为 5 分钟内可执行动作，steps 0–3 且每步带分钟数；≤5 分钟任务 steps 为空
- [ ] 超时/报错/空返回走规则模板并标 `source=fallback`，流程不中断
- [ ] 分析后改标题保留旧拆分、`analysis_stale=true`，不自动清空、不自动重调
- [ ] 采用版可编辑，模型原始版保留；结算复述使用采用版

## F3 计时与有效性

- [ ] 只有正计时，无暂停；重复开始复用 active 会话
- [ ] 满 5 分钟懒计算标记完成，完成时刻为 `started_at + 5min`，界面轻提示一次且计时继续
- [ ] <5 分钟结束：`status=discarded`、`duration_sec` 为空、不累计、不加星、不给投递机会、不计连续
- [ ] ≥5 分钟结束：`duration_sec` 写入、当天累计与星星更新
- [ ] 刷新/断网/锁屏后按服务端时间续算
- [ ] 跨零点场次归属 `started_at` 自然日，首页优先显示进行中场次
- [ ] 180 分钟自动结束，按 180 分钟计入

## F4+F5 结算与感想

- [ ] 结算页一屏同时展示数字、星星动画、连续天数 +1
- [ ] 四步顺序固定：感想 → 投递 → 处理信箱 → 随机回顾；① ② ③ 可跳过
- [ ] 中途离开后按 `settle_step` 直接跳到断点，不重复结算、不重复 +1
- [ ] 感想只写一次、历史只读，空提交视为跳过
- [ ] 断签后首次完成显示「新的一条线，从今天这 5 分钟开始」
- [ ] 四步完成后显示固定彩蛋「来自宇宙的音讯」

## F7 星星与连续

- [ ] 5 / 15 / 25 分钟对应 Lv1 / Lv2 / Lv3，只升不降且封顶
- [ ] 一天一颗星；一天最多 +1 连续；多场只累计时长
- [ ] 断签次日当前连续归零，历史最长与累计完成天数保留
- [ ] 星墙 14 天区分亮星 / 当天未完成 / 空心断签
- [ ] 客户端时间不参与任何判定；跨零点继续时长只进开始日星星

## F6 信箱与投递

- [ ] 每场有效学习 1 次投递机会，同场只投 1 封；可选择不寄出且不影响后续场次
- [ ] 拒收（满 3 封）/ 收件人不存在都不消耗机会，可改寄；发出记录标「未送达」
- [ ] 投递先校验收件人与容量、再写幂等键与信件（同一事务），拒收不留下已投递记录
- [ ] 并发投递时只有 1 封成功，未处理信箱永不超 3 封（行锁生效）
- [ ] 收藏幂等只入库一次；放弃信件当天 24:00 后失效且不进入历史
- [ ] 历史信箱只存收藏，超过 100 封静默删除最旧
- [ ] 今天未完成 5 分钟时信箱入口置灰并显示「完成今天的学习后开启」
- [ ] 学习期间信件静默投递；结算页显示「专注时收到 N 封信」，对方学习中则信件带「专注时投递」标签

## F10 随机回顾

- [ ] 抽取排除本场与当天，来源为本人已完成历史
- [ ] 展示日期 + 任务原文 + 感想（无感想只显示任务原文）
- [ ] 无历史时只显示「等待宇宙的讯息」
- [ ] 每场结算只出现一次，可跳转该日详情

## F8 记录查询

- [ ] 全部 / 区间 / 单日三种查法均可独立使用且只读
- [ ] 同日多场标注「第 X 场」并横向并列
- [ ] 区间汇总含完成天数、累计时长、完成率；起止颠倒自动纠正并提示
- [ ] 空态显示「还没有记录，今天这 5 分钟就是第一条」，不显示 0 值表格
- [ ] 星墙点击某天可进入单日详情

## 架构与工程红线

- [ ] 依赖方向仍为 `routers → services → models`；无 router 互相 import
- [ ] 取时间只用 `backend/app/clock.py`，前端只用 `useServerClock`；无 `datetime.now()` / `new Date()` 越界
- [ ] HTTP 只走 `client.ts`；未引入第二套业务状态或平行写入
- [ ] 未新增依赖、未改启动方式、未放宽 `test_architecture.py` 棘轮
- [ ] 新增文件（stars / progress / record / review）理由已写在 Spec 第 4 节
- [ ] 后端全量 pytest 已运行通过（区分「已编写」与「已运行」）
- [ ] 前端 `npm run lint`（0 error + 仅 shadcn 固有 1 warning）与 `npm run build` 通过
- [ ] 演示脚本（brainstorming §9）可在本地三服务上完整复现
- [ ] Spec 第 8 节已回填执行结果、未验证项与遗留问题
